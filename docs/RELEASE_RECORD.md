# 케셰브 릴리스 기록과 새 환경 재현 기록 (22단계)

이 문서는 **학생 진술**입니다. 서버가 새 환경에서 실행했다는 뜻이 아니며, AI 원문 검토는 실행 성공 증명이 아닙니다. 비밀값·로컬 절대경로는 적지 않습니다.

## 1. 대상 버전

| 항목 | 값 |
|---|---|
| 저장소 | https://github.com/Lui-die-lui/choi-bujang-secret-vault |
| 브랜치 | `assignment` |
| 재현한 커밋 | `a9096cdecf3d96970bc8a08e97d3751ed62c846b` (21단계 문서 커밋, 40자리) |
| 앱 시작 틀 버전 | 0.2.11 (`on-client/package.json`) |
| 이 기록이 들어간 커밋 | 이 문서만 추가한 바로 다음 커밋입니다. 코드는 재현한 커밋과 같으며, 해시는 문서 안에 적을 수 없어 `git log -1`로 확인합니다. |

재현한 커밋과 이 문서를 담은 커밋은 다릅니다. 아래 결과는 **재현한 커밋** 기준이며, 이 문서를 담은 커밋에서 다시 실행한 결과가 아닙니다. 서로 다른 커밋의 결과를 합쳐 전체 성공으로 쓰지 않았습니다.

## 2. 재현 환경과 절차

| 항목 | 내용 |
|---|---|
| OS | Windows 11 Home |
| Node.js / npm | v22.20.0 / 10.9.3 (수업 기준 24.19.0은 **미확인**) |
| 새 폴더 | 원래 작업 폴더 밖의 임시 폴더에 새로 만든 빈 폴더 |
| 의존성 설치 | 하지 않음. `on-client`는 외부 npm 의존성이 없음 |
| 인증·설정 파일 | 원래 폴더의 `.env` 등을 복사하지 않음 |

절차(실제 실행한 순서):

1. 원래 작업 폴더는 건드리지 않고, 빈 폴더에서 `git clone -b assignment <저장소 URL>` 실행
2. `git rev-parse HEAD`로 위 40자리 커밋과 같은지 확인 → 같음
3. `on-client` 폴더에서 `npm run check` 실행 → 오류 출력 없음
4. `ON_PORT=5198`로 `node src/server.mjs` 실행(원래 폴더의 실행과 포트가 겹치지 않게 함)
5. `GET /`, `GET /api/events` 요청
6. 시간 제한으로 종료(`Ctrl+C`와 같은 종료는 수동으로 시험하지 않음)

관찰 결과:

| 확인 | 결과 |
|---|---|
| 복제한 `HEAD` | 재현한 커밋과 일치 |
| `docs/STUDENT_RUNBOOK.md` 존재 | 있음 |
| 서버 시작 출력 | `케셰브 연결 확인: http://127.0.0.1:5198` |
| `GET /` | 200 |
| `GET /api/events` | 503 (`ENGINE_NOT_CONNECTED`, 기본 어댑터가 `disconnected`라서 예상된 결과) |
| 브라우저 화면 | **미확인** (브라우저로 열어 보지 않음) |

## 4. 버전과 지원 범위

- **상태: 검증 중인 버전입니다.** v1.0이 아니며 실제 운영 인증이 아닙니다. 22단계 통과는 원문 검토 기준의 수료이며 실제 동작 증명이 아닙니다.
- 지원 환경: Windows 11, Node.js v22.20.0에서 서버 시작과 `GET /`을 확인했습니다. 그 밖의 OS·Node 버전·브라우저는 지원 여부를 확인하지 않았습니다.
- 기본 실행은 실제 접근 제어·XDR 시스템에 연결되지 않은 상태(`disconnected`)입니다. `npm run demo`는 예제 자료이며 실제 연결이 아닙니다.

## 6. 이동 가능한 구성

- 로컬 절대경로를 쓰는 커밋된 파일은 없는지 검색했습니다(검색한 범위: 저장소 전체, `node_modules`·`.git`·`CHECK.md` 제외). 발견되지 않았습니다.
- 설정 견본은 `on-client/.env.example`(비밀 없음)입니다. 실제 `.env`, 키, 토큰은 커밋하지 않으며 새 환경에서 복사하지 않았습니다.
- 새 환경에서 필요한 것: Node.js와 이 저장소의 해당 커밋. `on-client`는 별도 `npm install`이 필요 없습니다.
- 1~12단계 자료실(저장소 최상위 `api/`, `src/`)은 별도의 `npm install`, Supabase 환경변수, `docs/sql/*.sql` 실행이 필요하며 이번 재현에서는 **실행하지 않았습니다**(`README.md` 참고).

## 7. 데이터 보존 계획

| 데이터 | 위치 | 보존·백업 | 복원 | 제한 |
|---|---|---|---|---|
| 학생 코드·문서 | Git 저장소(`assignment` 브랜치) | `git push`로 원격 보관 | `git clone`으로 같은 커밋 복원 | 커밋하지 않은 변경은 포함되지 않음 |
| 1~12단계 자료실 데이터(가상 메모, 기기 등록부, 회수 기록) | Supabase | 이 저장소는 스키마 SQL(`docs/sql/`, `supabase/`)만 보관하며 데이터 백업은 하지 않음 | SQL을 순서대로 다시 실행하면 스키마만 복원됨 | 데이터 복원은 이 저장소 범위 밖, **미확인** |
| 조치 접수 저장소 | `on-client/src/actions/store.mjs`가 설정된 경로의 SQLite 파일 사용 | 실제 경로와 내용은 확인하지 않음 | **미확인** | 이번 환경에서는 조치 설정이 없어 사용하지 않음 |
| 키·토큰·`.env` | 로컬 파일, 서버 보관소 | Git에 넣지 않음. 별도 백업하지 않음 | 담당자가 다시 발급 | 학생이 값을 문서에 적지 않음 |
| `bundle-notes.json`, `artifacts/submission.json` | 로컬 | 커밋하지 않음 | 해당 없음 | 제출 도구가 다시 만듦 |
